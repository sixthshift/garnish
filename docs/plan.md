# Plan

Implementation plan for garnish, stages 7 to 13 (what surrounds the recipe: the shopping list, sub-recipes and conversions, the meal plan, export and import, a bundle of small parity items, a second pass over the import, and the household's own voice for the steps), written to be executed one task per loop iteration with no human present. Decisions live in [decisions.md](decisions.md), shape in [architecture.md](architecture.md), boundaries in [scope.md](scope.md). Run it with `/ailoop` (see `.claude/skills/ailoop/SKILL.md`): one fresh subagent per task, the orchestrator verifies and records. This file is edited only by the orchestrator. Completed stages live in `docs/plans/`; stage 1 is [v1-foundations.md](plans/v1-foundations.md), stage 2 [v2-ui.md](plans/v2-ui.md), stage 3 [v3-parsing.md](plans/v3-parsing.md), stage 4 [v4-editor.md](plans/v4-editor.md), stage 5 [v5-recipe-page.md](plans/v5-recipe-page.md), stage 6 [v6-step-card.md](plans/v6-step-card.md).

## Loop protocol

What one task looks like, whoever runs it (an ailoop subagent, a /loop firing, or a person):

1. Read this file. Read `CLAUDE.md`. Do not re-read the other docs unless a task points at them.
2. Pick the first unchecked task whose dependencies are checked. Milestones run in order; tasks within a milestone run in order unless marked `∥`. A `!` before the task id asks `/ailoop` to dispatch it on a stronger model; the skill's Model section has the rules.
3. Do that one task. Nothing else. No drive-by refactors, no adjacent tasks.
4. Verify with the task's own check. Then run the full gate:
   ```
   bun run check     # tsc --noEmit
   bun run test      # vitest run
   ```
   Both must pass. A failing gate is not done. Fix it or revert the task.
5. Commit with a one-line message naming the task id, e.g. `M1.3 recipe document schema`. Attribution trailer per `CLAUDE.md`.
6. Report. Under `/ailoop` the orchestrator ticks the task, appends the Log line and commits; a subagent never edits this file. Under `/loop`, do it yourself.
7. Stop. One task per iteration.

Rules:

- **Blocked?** Write the blocker under Blocked with the task id and what you tried. Move to the next task that does not depend on it. Never guess past a blocker on a decision; guess freely on implementation detail, and when unsure copy Mealie.
- **Question for Jason?** Write it under Questions. Pick the Mealie answer and continue. Do not stop.
- **Found a design gap?** Add a row to `decisions.md`. Do not edit existing rows. Note it in the Log.
- **Framework questions?** TanStack Start docs at https://tanstack.com/start/latest. Server functions for app calls, server routes only under `src/routes/api/`. SPA mode stays on.
- **UI element needed?** Check the design system's exports first (`node_modules/@sixthshift/design-system/package.json`). Build locally only if absent, under `src/components/ui/`.
- **Task too big for one iteration?** Split it in place into `Mx.y.a`, `Mx.y.b`. Do the first part.
- **Tests:** every pure function and every API route gets tests in the same task that creates it. No task is done with a TODO test.
- **No new dependencies** beyond the list in M0 without a decisions.md row saying why.

## Stages 7 to 13: around the recipe

Six stages built the recipe: the model, the parser, the editor, the import, the page, the step card. It is at parity with Mealie and Tandoor or ahead. What both incumbents have that garnish does not is everything around the recipe, and the schema has anticipated most of it since stage 1: `aisle`, `food.skip_shopping`, `unit.standard_*`, `food.recipe_id`, the merge rule in decision 13, the disabled "Add to shopping list" button from M30.4.

The order, and the garnish-shaped version of each:

- **Stage 7, the shopping list.** One list, no owner. Merge by food and unit, expand a line to its sources, group by aisle. Add from the recipe at the current scale. The garnish-specific problem: the supermarket is not on the LAN, so the list must open and tick offline. That is the app's first queued write.
- **Stage 8, sub-recipes and conversions.** A food that points at a recipe renders as a link with a scale hint; conversions per food so a cup and 300 g of flour merge; then the list scales through a sub-recipe. Conversions before expansion, or the list gets two flour lines.
- **Stage 9, the meal plan.** A week strip, a recipe or a line of text on a day, one tap adds the week to the list. No meal types, no per-person plans.
- **Stage 10, out and in.** JSON and Cooklang export, import from Mealie and Tandoor backups (the adoption path neither incumbent offers), then `claude -p` import as the rung under JSON-LD, landing on the existing review step.
- **Stage 11, small parity items.** Step images, servings on a cook log entry, an ingredient preview on the card, a fetch that gets past a bot wall. Independent of each other and of the stages above; `∥`.
- **Stage 12, the import pipeline.** Stage 10 built the rungs; this makes them one pipeline with a language model as the reader. schema.org has no place for which part an ingredient belongs to, so on any page with sections the rules produce the wrong shape by construction, and the JSON-LD's real value is as ground truth rather than as the answer. After this, every page is read by the model when one is configured, with the JSON-LD as its anchor: the page owns the lines and the steps, the model supplies the parts, and a mechanical check discards any answer that changed the content. The rules result shows meanwhile and is what you get when no model is configured, or it fails, or it is rejected. The model is a hosted one behind one OpenAI-compatible HTTP call, configured by environment, defaulting to Gemini's free tier; `claude -p` goes. Pasted HTML goes through the same path as a fetched page.
- **Stage 13, the house style.** Every site writes its steps differently: one chef gives six micro-steps, another one paragraph. The import keeps the author's words on purpose (stage 12's check forbids anything else), so the collection reads in a dozen voices. This stage adds a second, separate pass that rewrites the steps into the household's own: a **style guide** kept as a list of short statements in Settings, each on or off by default and toggleable per run; a **Restyle** action on any recipe that sends its steps and the ticked statements to the model; a **facts check** that a rewrite may change words but not numbers or ingredients; and a step-by-step **diff** to approve. Steps only. Ingredient lines, quantities, parts and metadata are frozen, the original steps are kept so a restyle can be redone from them, and the recipe says it was restyled. Neither incumbent has this; there is no Mealie answer to copy, so its first task carries the decision.

Migrations run 005 to 010 in stage order. Each new table gets a Drizzle mirror and the drift test. Each stage's first task carries the decisions row for its model.

Not in these stages, and not to be re-raised without a decisions row: nutrition and costing, cookbooks or any second organiser beside tags (decision 42), comments, share links, categories and tools, per-person or per-meal-type planning, inventory (intent.md), and a DOM test environment (the stage 5 question still stands for Jason).

## M36 The import pipeline

What `recipe_scrapers` gets right is one rule, in its ingredient-group reader: the JSON-LD owns the lines, the HTML only says which heading each sits under, and a count mismatch throws the grouping away. This milestone builds that rule with a language model in place of per-site selectors, and makes the model the default reader of a page rather than the fallback under the rules: the rules cannot allocate ingredients to parts, and the format needs that. The model is a hosted one behind a single OpenAI-compatible HTTP call, not `claude -p`: the task does not need frontier capability, the CLI is a bespoke integration on a moving target, and a container should not need a login step. Order matters: M36.1 swaps the backend every later task talks to, and M36.2 changes the import document every later task reads. `ImportedRecipe` gains two fields along the way: `pageText` (M36.3) and `check` (M36.5).

- [x] **! M36.1 One HTTP call to a hosted model.** `src/server/aiImport.ts` drops the `claude` binary: `claudePath`, `CLAUDE_BINARY`, `claudeArgs`, `spawnRunner` and the CLI envelope parsing go. In their place `fetchRunner` POSTs to `${AI_BASE_URL}/chat/completions` with `Authorization: Bearer ${AI_API_KEY}`, body `{ model: AI_MODEL, messages: [{ role: "user", content: prompt }], response_format: { type: "json_schema", json_schema: { name: "recipe", schema: SCRAPED_JSON_SCHEMA, strict: true } }, temperature: 0 }`, `AbortSignal.timeout(AI_IMPORT_TIMEOUT_MS)`, and returns `choices[0].message.content`; `parseAiAnswer` reads that string (keeping `stripFence` for models that fence anyway). `AiRunner` becomes `(prompt, timeoutMs) => Promise<string>` and stays injectable. `aiConfigured()` is `AI_API_KEY` being set; `AI_BASE_URL` defaults to Gemini's OpenAI-compatible endpoint and `AI_MODEL` to its current Flash model, so the free tier is one variable, and Mistral, Groq, OpenRouter or a LAN Ollama are a base URL and a model name away (Ollama takes any non-empty key). Errors keep their four kinds: no key is `unavailable`; a 401/403 says the key was rejected, a 429 says the provider is rate-limited and to try again in a minute, another non-2xx names the status (`failed`); the abort is `timeout`; a non-recipe answer is `malformed`. Plain `fetch`, no SDK. `aiImportAvailable` reads `aiConfigured()`. `docker-compose.yml` passes the three variables through from the host (`${AI_API_KEY:-}` and so on; `test/docker/compose.test.ts` follows) and README gains an AI section. The Settings note replaces `claude setup-token` with the three variables and one line that the Gemini free tier may train on what is sent, which for a public recipe page costs nothing. `CLAUDE.md`'s and `AGENTS.md`'s AI line, `intent.md` line 48, `scope.md` line 19 and `architecture.md`'s import line say "a hosted model over an OpenAI-compatible endpoint" instead of `claude -p`. decisions.md row: reverses row 11 and the mechanism in row 74 (row 12's setup-token note lapses with it); the reasons are the three in this milestone's preamble plus: recipes are public content, so a tier that trains on prompts is free in every sense.
